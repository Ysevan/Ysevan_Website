### 此前已记录的未发布改动（保留历史，非本次新增）

以下条目记录此前各轮的改动与当时验证；其中大屏缩放、三栏、底栏、目录/工具抽屉和 3D 的旧形态，以 v1.8.0 / v1.8.1 及 design-proposal.md §13、§14 的最新约定为准。

- **老浏览器上的大屏放大台阶从三档补成六档。** 宽屏上页面按「窗口宽 ÷ 1440」平滑放大；太老、算不了这个公式的浏览器（Chrome 111、Safari 15.4、Firefox 108 以前）改走写死的台阶。台阶原来只有三档（1600 / 1920 / 2088），屋主台式机那种 2040 宽的屏只放大到 1.33 倍。现在照四个工具共用的视觉规格补成六档（1600 / 1800 / 2000 / 2200 / 2400 / 2560），同一块屏给 1.39 倍，离平滑公式的 1.417 只差 2%。新浏览器不走这一段，没有任何变化。
- **只用键盘时，「外观：浅色 / 深色 / 自动」终于能换档了。** 这组开关是按单选组做的：Tab 只进当前选中的那一档。但以前方向键不起作用，Tab 进去之后就换不了。现在用 ← →（或 ↑ ↓）在三档之间换，到头会绕回另一头；Home / End 跳到第一档 / 最后一档。按下立刻生效，页面不会跟着滚。强调色圆点不变，仍是每个都能 Tab 到。
- **搜索框边打字边出联想。** 在顶部搜索框里打字，框下面马上弹出一个小浮层，列出最相关的业务：电脑上最多 6 条，手机上 5 条。每条是业务名（打中的字高亮）+ 它所在的上级目录（一行小字，太长就省略）+ 右边一枚小标签：交易码完全对上时写「交易码 G04002」，正文里提到时写「正文N处」，业务名本身就带这个词时不出标签。最后一条固定是「查看全部 N 个结果」。
  - **怎么用**：鼠标点一条，或者用 ↑↓ 选中再按回车，直接打开那个业务；**一条都不选、直接按回车，和以前一样进搜索结果页**。按 Esc 先收起浮层、框里的字留着；再按一次 Esc 才清空搜索框（和以前那一下一样）。浮层开着时焦点一直留在搜索框里，可以接着改词。
  - **一个都没搜到时**：浮层写「没有直接命中「xx」，名称相近的业务：」，列出最多 3 个名字相近的业务（标签写「名称相近」），不出「查看全部」；连相近的都没有就只写「没有找到相关业务」。
  - **看起来**：浮层是实色的白底（深色下是深灰实色），不加磨砂——它压在正文上面，要实色才读得清，而且磨砂在没有独立显卡的电脑上会拖慢整页。弹出和收起只有一下很轻的淡入淡出，条目随打字直接换、不做动画；系统开了「减弱动态效果」时连这一下也没有。深色、增强对比度、六个强调色下都跟着换色，打印稿不受影响。
  - **读屏**：停手约 0.4 秒后报一句「6条联想，上下键选择」（没搜到时报「没有直接命中，3个相近业务」），不会每敲一个字读一遍。
  - 按 `?` 打开的快捷键说明同步改了：↑↓ 与 Enter 两条加上了「搜索联想」，Esc 的逐层退出里在「清空搜索框内文字」之前加了「收起搜索联想」。
  - 手册里没有 `search-module.js`（拷漏了、被杀毒软件拦了）时，联想整块不出现，搜索框照旧只有回车进结果页这一条路，控制台一个字都不打。
- **用拼音等输入法打字时，选词的按键不再被网页误当成操作。** 选词的回车、翻候选的方向键、取消选词的 Esc 都归输入法，网页一律不接。这一轮顺带补了同一类的四个老漏洞（改动前就有）：
  - 拼音打到一半按回车选词，搜索框会直接提交，拿拼音字母去搜（合成中的「kai」按回车，结果页搜的就是「kai」）；
  - 拼音打到一半按 ↓ 翻候选，焦点会被从搜索框拽进结果列表；
  - 拼音打到一半按 Esc 取消选词，会把搜索框整个清空；
  - 在目录过滤框里拼音打到一半按 Esc 取消选词，会把过滤词清掉（窄屏抽屉里也一样，但抽屉本身不会被关掉——这一点原先猜错了，实测抽屉一直开着）。
  四条都是在改动前的版本上用模拟输入法（Chrome 调试协议）复现出来、改动后复测消失的；**真机上的中文输入法还没有逐一试过**。回车那一条只拦「确实还在选词」的那一下，不拦手机键盘上的「搜索」键。
- **顶部搜索框里不再有两个「×」。** 以前框里有字时，右端并排两个清除按钮：一个是浏览器给搜索框自带的，一个是手册自己的。现在把浏览器自带的那个藏掉，只留手册自己的（它会把光标放回框里、顺手收起联想浮层）。目录过滤框没有自己的清除按钮，浏览器自带的那个照旧留着。
- 回归测试脚本启动浏览器时一律静音（手册本身没有声音，这条防的是将来）。
- **这一轮故意没做的。** 屋主给了六个交互组件，逐个对过岗岗现有的交互，**只有「输入联想浮层」对得上**（岗岗本来就有搜索框，只是以前只能回车提交）。其余五个都不做，不为了套组件去造新功能：
  - 多选筛选标签：岗岗的分类（对私 / 对公）是单选切换，搜索与目录都没有「按分类筛选」这回事；
  - 可删除标签：岗岗没有任何「输入标签」的地方；
  - 拨动字号刻度：岗岗没有字号调节，字号靠窗口宽度自动适配与浏览器缩放（⌘+ / Ctrl+）；
  - 按压倾斜卡片：岗岗没有首页，目录是列表不是卡片，「业务排成卡片墙」早在 design-proposal.md §9.6 就否掉了；
  - 长按录音条：岗岗没有语音输入。
  联想浮层本身也只做了「边输边出、选中直达」这一半，不做「选中后以标签形式插入正文」那一半——手册是给人读的，没有可以往里插东西的正文。全部取舍写在 design-proposal.md §11。
- **（交互升级第二批）点截图时，图从原来的位置放大出来；关掉时缩回原处。** 以前点正文里的截图缩略图、或速查卡胶片条上的小图，灯箱是「啪」一下整块出现，关掉时也是一下消失，眼睛得重新找刚才看到哪儿。现在打开时，那张小图从它在页面上的位置平滑放大到灯箱里大图的位置（约 0.26 秒），暗色遮罩与灯箱卡片同时淡入；关闭时（点「关闭」、点遮罩、按 Esc）大图缩回页面上那张小图的位置（约 0.2 秒），落点就是刚才点的地方。小图本来是裁过的（只露截图上部），放大过程中裁切是连续展开的，不会先变形再跳成整张。
  - **什么时候只淡出、不缩回**：在灯箱里放大过（点了「放大」或按了 +）；或者翻到了别的图，而那张图在页面上的小图不完整地在屏幕里（滚出去了、被顶栏或手机底部快捷栏挡住一截、在横滚的胶片条里被卷走了）——没有可落的地方，就原地淡出。
  - 关闭动画那 0.2 秒里灯箱不接点击；这时再按一次 Esc 会立刻关掉，不再播第二段。打开动画还没播完就按 Esc，也是立刻关掉。换业务、后退前进时灯箱是当场关掉的（正文要重画，小图马上就没了，没有落点）。手机上的返回手势：浏览器允许网页接管时走缩回动画，不允许时由浏览器直接关掉，收尾照样干净。
  - 系统开了「减弱动态效果」，或浏览器太老（不支持网页动画接口、或没有原生弹窗）时，灯箱和以前一样瞬开瞬关。
  - 只动位置、大小和透明度，不加磨砂；焦点、键盘、读屏一字未改（打开时焦点在「关闭」按钮上，关掉后回到点开它的那张小图）。
  - **没有独立显卡的电脑上会轻微顿一下**：屋主台式机那种靠 CPU 画图的机器上，每次开合会有一两帧停 1/30 秒（平时是 1/60 秒），不连着顿。量过，原因是页面本身的磨砂：灯箱淡入淡出时，底下整屏的模糊每一帧都要重新合一遍，把磨砂关掉就不掉帧。关不关磨砂是四个工具一起定的事，这一轮没动，数字见 design-proposal.md §12.6。
- **（交互升级第二批）复制交易码后的「已复制」小气泡有了指向交易码的小箭头，出现和消失都变轻了。** 以前是一个没有箭头的小黑块，出现、消失都是硬切。现在气泡下沿有一个小三角指着被复制的那枚交易码；出现时从交易码那一侧轻轻弹起（约 0.16 秒），1.4 秒后先淡出（约 0.14 秒）再消失。连续点两个交易码时，旧气泡立刻消失、新的重新弹出。
  - **贴边会自己躲开**：交易码靠近窗口左右边时，气泡整体挪回屏幕里（离边 8 像素），小箭头反着挪、仍然指着交易码正中；交易码紧贴在顶栏下面（或贴在一个会裁切内容的滚动框顶上）时，气泡改到交易码下方、箭头朝上。
  - Windows 高对比度模式下，气泡带一圈边框、箭头仍是三角——不专门处理的话，这种画法的箭头在高对比度下会变成一块实心方块（实测过）。
  - 读屏照旧只播「G04002 已复制」那一句，气泡本身读屏读不到；「减弱动态效果」下没有弹起和淡出，1.4 秒到点直接消失。
- **（交互升级第二批）手机上（窗口不宽于 600px）点「设置」拉起的速查卡，改成从底部快捷栏后面升起、收起时落回去。** 以前是瞬间出现、瞬间消失。时长与曲线和目录抽屉完全一样（0.22 秒），两个底部抽屉手感一致；暗色遮罩也和目录抽屉一样随开随关、不做渐变。收起那 0.22 秒里抽屉不接点击，焦点在一开始就回到「设置」按钮。窗口宽于 600px（速查卡是正文顶部的横条或右栏）时一切照旧；专注模式下右下角那枚「退出专注模式」浮动按钮不受影响；「减弱动态效果」下瞬开瞬关。
  - **为什么没照目录抽屉的写法**：目录抽屉关着的时候其实是「藏在屏幕下面待命」。速查卡要是也这么写，从宽窗口拖窄到 600 以下、或退出专注模式的那一下，会看到一整块速查卡从几乎全开的位置滑下去一闪（实测约 0.2 秒）。所以速查卡关着时仍然不是抽屉，只在收起那一小段临时撑住抽屉形态、播完就撤。
- **这一轮（第二批）故意没做的。** 屋主又给了八个交互组件，逐个对过岗岗现有的交互，**对得上的三个做了**（卡片弹出详情 → 截图灯箱，气泡提示 → 复制气泡，结算栏弹出清单 → 手机速查卡抽屉），其余五个不做，同样不为了套组件去造新功能：
  - 按钮弹出菜单：岗岗全站没有「点一个按钮弹出一串选项」的地方；
  - 确认弹窗：岗岗没有任何确认弹窗，「清空勾选」「从常办移出」都是点了就生效，为了套组件加一道确认，等于每次多点一下；
  - 侧边推移抽屉：窄屏的目录抽屉是为单手拇指够得着定的底部形态，改成从左边推进来是换形态、不是升级；而且「推移」要给整页加位移，会把固定在屏幕上的底部快捷栏、浮动按钮和顶栏一起带偏；
  - 分类标签展开面板：分类只有对私 / 对公两个，灯箱里「按环节筛图」的 5 个短标签一行就放得下，没有需要展开的东西；
  - 日期弹出日历：手册里没有日期。
  全部取舍写在 design-proposal.md §12；版本号不动。

## [1.7.0] - 2026-09-23

- **全站改成「苹果液态玻璃风」，并加了两个开关：外观（浅色 / 深色 / 自动）与强调色（六个）（本版最大的变化）。** 页面底是三团很淡的光晕（跟着强调色走的一团 + 一团暖色 + 一团冷色），内容一律浮在半透明的白玻璃上；顶栏、目录栏、吸底条与手机快捷栏另加一层磨砂。六个强调色是**蓝（默认）、绿、靛、橙、粉、青**，在右栏「强调色」那一排点一下就换；外观那一排是「浅色 / 深色 / 自动」三选一。两项都记在本机浏览器里（`hb:mode` / `hb:accent`），下次打开还是它。六个强调色只差强调色那一组令牌与三团光晕，正文、卡片、圆角、阴影、打印稿全部一样，所以切换是瞬时的、不重新加载任何内容。**数据、业务功能与界面文案一行没动**，改的只有颜色、圆角、图标与磨砂。全部取值与核算见 design-proposal.md §10。
- **这一版之前还有两版，都被屋主否掉了、都没有发布过。** 留个记录：本轮先按「与刷刷统一配色」做了一整版（深色侧栏 + 刷刷红），屋主否决；改做「六套粉彩」（天蓝 / 薄荷 / 紫雾 / 糖果 / 海雾 / 暖雾），做完验完写完文档之后屋主仍然否决，原话是「刷刷的这些我觉得都不好看，你参考一下苹果的 UI 和配色」「UI 要适配我页面的缩放大小」「四个工具都用这套」。于是整版重做成现在这套苹果液态玻璃风，**四个工具（刷刷 / 岗岗 / plan / card）通用**。前两版的令牌留在 git 历史里，1.7.0 里没有它们的任何残留（`--side-*`、`--bg-gradient`、`--swatch-*`、六套粉彩的英文名已全部删除）。旧版本若存过粉彩的 `hb:palette`，读到时一律忽略，强调色从蓝重新开始；**旧的「界面主题」选择不会丢**——`hb:theme` 会被读一次当作新的外观初值并写回 `hb:mode`。
- **界面元素重做成苹果那一套**：目录栏是玻璃侧栏，每个业务条目前加了线条图标（选中项图标与文字一起变强调色）；速查卡的「编号 / 材料清单 / 风险摘要 / 截图」四节各有一个 32px 的彩色圆角方块图标，跟 iOS 设置里的那种一样；左上角品牌是一个强调色渐变的圆角方块 + 白色「打开的书」；风险行首的【禁止】【注意】做成了软底胶囊。**所有图标都是真的 SVG 线条图**（线宽 1.9、端点圆角），不是字符也不是 emoji。
- **左上角的品牌图标可以自己换，放文件即生效、不用改代码**：把 `assets/brand/brand-icon.svg`（或 1024×1024 的 `.png`，透明底白色线条）放进去，刷新就换上，图会自动缩到方块的 84% 并居中。屋主手绘的那一版（`brand-icon.svg` 在用、`brand-icon.png` 备用）**随 1.7.0 一起入库**；两个文件都删掉时会回落到内置的「打开的书」。怎么放、要什么规格写在 `assets/brand/README.txt` 里。
- **浏览器标签页上终于有图标了（favicon），而且跟着强调色换**：以前标签页那一格是空白的。现在挂上的是一枚「强调色亮渐变圆角方块 + 白色线条」，方块自带底色，浅色与深色标签栏下都看得清。**刻意没有直接拿屋主那张 `brand-icon.svg` 当 favicon**——它是透明底白线，压在浅色标签栏上等于隐形。线条形状与屋主那张逐字相同（路径内联进来，不外链，favicon 必须自包含），整块缩到 84% 居中，与左上角品牌方块里的比例一致；圆角取 iOS 图标那个比例（边长的 22.37%，1024 → 229）。首帧由静态文件 `assets/brand/favicon.svg`（默认蓝）负责，页面脚本起来后按当前强调色把它换成内联图，六个强调色各一枚，渐变两端直接读 CSS 令牌的计算值，改了令牌它自己跟着改、不用再维护第二张表。取值、做法与踩过的坑见 design-proposal.md §10.14c。
- **手机上（窗口窄于 600px）新增底部快捷栏**：三个按钮——目录、搜索、设置。目录唤出原来那个业务目录抽屉；搜索展开顶栏搜索框并直接聚焦；设置把整张速查卡当作底部抽屉拉起来（含外观、强调色、案头手册三个开关），最高占 70% 屏高、可滚。两个抽屉互斥，点遮罩或按 Esc 逐层退出，关掉之后焦点回到按下的那个按钮。这一档的顶栏只剩品牌图标 + 当前业务名，吸底条让位给快捷栏，浮动的「下一环节」按钮上移到快捷栏之上，底部留出手机的安全区。**窗口宽于 600px 时这条快捷栏整个不渲染**，桌面上既看不到也不占键盘 Tab 顺序。
- **大屏按比例放大、构图不变**（屋主在 2560 宽的 Windows 屏上要「跟 Mac 1440 一样」，四个工具统一）：以 1440 为基准，字号、间距、侧栏宽、圆角、图标、控件、正文行宽随窗口等比放大，2560 左右到 1.45 倍封顶；1440 及以下一个数值都不变。宽屏一律铺满窗口、不在中间缩成窄柱也不留两块空白——多出来的宽度只给中间的阅读栏（正文行宽仍居中收住，两侧是玻璃面板本体），不多加列。封顶倍数全站只有一处（`--scale-max`），屋主在大屏上看过嫌小，改一个数就整体放大。实现用的是标准 CSS 三角函数求「窗口 ÷ 1440」的比值，**没有用 zoom 或整页缩放**；不支持三角函数的旧浏览器按 1600 / 1920 / 2088 三档台阶放大。
- **响应式断点由 820px 改到 900px**（四个工具统一），并把字号、间距、侧栏宽全部改成随窗口连续插值（`clamp()`）。屋主要求「UI 要适配我页面的缩放大小」——这么做之后，浏览器缩放（⌘+ / ⌘-）等价于窗口变窄，不需要为缩放另设一套规则；任何一档都不会出现横向滚动条。四档形态：宽于 1120px 三栏、901–1120px 两栏（速查卡收成正文顶部横条）、601–900px 目录进抽屉、600px 及以下加底部快捷栏。
- **每个颜色仍分成「填充」和「文字」两档**：苹果系统色是按「压白底」设计的，直接拿来当字色压不住（蓝 `#007AFF` 压白 4.02、红 `#FF3B30` 3.99、绿 `#34C759` 只有 1.93，都够不着 4.5 的底线）。所以填充那一档只用来做底色、渐变、图形和图标底块，文字那一档一律走苹果 HIG 的「增强对比度」系统色（四个工具用同一组值），并逐个核过**压白、压玻璃叠光晕最不利的那一角、压自己的浅底、压实色面**。这条约定是本版颜色体系的地基，改颜色前请先读 design-proposal.md §10.6。
- **主按钮按屋主要求改成「和左上角品牌图标同一条亮渐变 + 白字」，这是一处已知的可读性例外。** 屋主原话：「所有颜色的按钮色可以和页面左上角的颜色一样浅一点」。白字压这条亮渐变达不到 4.5——实测浅色下深端 2.20–5.65、浅端 1.41–3.52（六个强调色里只有靛过 3:1）。这里**不声称达标**：唯一的补救是给白字加了一道很淡的文字投影（四个工具一致），没有压深渐变、没有加描边。影响是弱视用户或强光下手机屏上，主按钮上的字会比别处难读；好在主按钮承载的动作（搜索提交、下一环节、跳到正文、专注模式）在页面上都另有路径（回车、锚点条、目录、快捷键），不会因此做不成事。决定来源、六色实测比值与完整理由见 design-proposal.md §10.10。
- **深色主题**：底色六个强调色共用（底 `#0B0C10`、玻璃深灰蓝），只换强调色相与三团光晕。会互相嵌套的那几个面（弹层、表格行、计数胶囊、分段轨道）本版**整组改成实色**，半透明叠加把对比度提亮那个老问题从根上没有了。**114 张白底截图的底板在深色下照旧保持浅色**，不会刺眼。
- **磨砂仍然只放在一屏大小的层上**（2026-09-22 真机复核定下的规矩，本版沿用并扩到五处）：顶栏、目录栏的吸附区、吸底条、窄屏目录抽屉，外加这一版新增的手机快捷栏与底部抽屉——它们的高度都是常数。**随正文长的面（阅读栏、右栏、卡片）一律不挂磨砂**：最长的业务下这几栏各高约 19,570 像素，挂磨砂会超过显卡纹理上限导致整栏不渲染。半透明观感改由不透明度单独承担（阅读栏与右栏 78%，深色 72%）。不支持磨砂的浏览器（以及系统开了「减少透明度」的用户）玻璃统一提到 90% 不透明兜底；判断「支不支持」时连 `-webkit-` 前缀写法一起测，所以 iOS Safari 18 以前的老 iPhone 不会被误判、仍然是玻璃。细节见 design-proposal.md §10.11。
- **对比度全量核算，两条路互相补位**：① 在真实页面上逐元素截图取底色像素众数，浅/深 × 六个强调色 × 35 个元素共 **420 对断言**；② 再用公式直接压「玻璃叠光晕最不利角」的合成色核一遍。两条路各抓到一处像另一条漏掉的问题（公式抓到粉色光晕下顶栏里的当前环节名只有 4.35，像素抓到深色弹层底太亮导致三个强调色的选中项只有 4.17–4.25），都已修掉。最终：**正文一律 ≥4.5、图形一律 ≥3，零例外**——除了上面那条主按钮，以及文档 §10.9 里逐条写明的六处「SPEC 值在岗岗落不下去」的调整（浅底改实色、粉/青的光晕各压一档、浅色次级字统一 .76（四家统一，一个值）、三级色不用装饰档、目录分组标题保持 13px、深色弹层底压深）。
- **3D 案头手册跟着强调色换封面**：六个强调色各一组封面 / 书脊 / 书签的取色，深色下整体压暗、书页改 `#2C2C2E`。**换壳这件事上，模型、动画与 `desk-book.js` 只改了一行**——把它监听的属性名从旧的 `data-theme` 换成 `data-mode` 并加上 `data-accent`，其余一字未动。（同一版里另有一轮改了 `desk-book.js` 的上下文探测与档位，即下面那条「精简档」；模型、着色器与动画在那一轮也是一行未动。）
- 打印仍然是白纸黑字，**版式一个数值没改**：光晕、玻璃、磨砂、阴影与文字投影全部关掉，两种画法的图标一起撤掉（复印会糊成黑块），六个强调色打印出来是同一张纸。1.6.0 修过的那条打印选择器权重问题跟着属性改名一起同步（`data-theme` → `data-mode`，四条选择器形状与权重不变）。
- 两个开关本身：外观是「浅色 / 深色 / 自动」分段控件（单选组语义，读屏播报「外观已切换为深色」，「自动」那一档会说明当前跟随系统解析成了哪一档）；强调色是六个色圆点，圆点旁的中文名平时压成 0 宽、鼠标悬停或键盘走到时就地展开（读屏另有中文可及名，所以色觉障碍者与读屏用户都答得出这是哪一个）。键盘 Tab、Enter、空格与 Esc 的规则一字未改。手机地址栏的主题色跟着外观走（浅 `#F4F5F9` / 深 `#0B0C10`）。
- 全量复核：仓库里的 A/B 回归套件以**本轮改动前的工作区状态**为基线，在默认与 `?desk3d=force` 两个模式下把全部 81 个业务和 10 个搜索词逐字比对，被测与基线都零报错，突变自测 9 条全部如期（8 条报红，第 9 条是对照组「在约定位置放合法装饰」，如期通过）。回归套件同步扩了去装饰白名单（五个开关类名两侧同剥，加上 `body` 直属的手机快捷栏与品牌图标 `<img>`），突变自测从 6 条加到 9 条（新增「同一个开关放两个」「快捷栏挪进正文壳」「品牌图标放到品牌链接之外」三条，都必须报红）。控制台在浅色、深色、六个强调色、案头手册 force、搜索页、增强对比度、窄屏抽屉与手机快捷栏各状态下零错误零警告。

- 新增「案头手册」3D 点缀（设计见 design-proposal.md §9）：宽屏（窗口宽于 1120px）阅读业务时，速查卡滚出视口后，右栏末尾滑进一本摊开的纸质小手册并贴在工作台头下方停住（约 210×200 像素）。第一次进入视口时约 0.8 秒翻开封面；向下阅读时 8 张书页按本业务的阅读进度一页页翻过（正文从头读到尾正好翻完 8 页，140ms 阻尼），正在翻的那页弯着翻；鼠标在页面上移动时手册朝指针方向倾斜不超过 6°、书签丝带跟着轻摆（只在有鼠标的电脑上）；换业务时约 0.6 秒合上再翻开；不动的时候一帧都不画。纯装饰，不承载任何信息，读屏与键盘路径一步未变；书页上只有程序生成的淡墨横线，**不画任何截图或正文**，也没有新增任何图片、贴图或模型文件。
- 长相是同一套纸与水彩：着色全部自写，三档平涂色阶、背光面掺一点海湾蓝冷影、纸纹颗粒（亮度 ±3%）、每个面边缘一圈略深的颜料边、底下一块柔边假投影，没有高光与实时阴影。**封面跟着强调色走**：封面就是当前强调色的实色（默认蓝 `#007AFF`），书脊与书签丝带深一档（蓝下是 `#0058B8`），冷影取强调色的渐变浅端 `--accent-2`（蓝下是 `#5AC8FA`），书页是近白的纸色 `#FDFDFD`；六个强调色各一组封面 / 书脊 / 书签 / 冷影。深色主题下封面整体压暗一档（蓝下 `#075CB3`、书脊 `#054281`），书页改成 `#2C2C2E`。换外观或换强调色时当场换色、不用刷新。颜色全部走 `styles.css` 的 `--book-*` 令牌（取色随上面那条玻璃风一起定下，见 design-proposal.md §10 表 B）。

- 什么时候不出现——不出现时 three 与 GSAP 一个字节都不下载，页面与 1.6.1 逐项一致：系统开了「减弱动态效果」（开关也不显示，存下的「开」不起作用；页面打开期间切换这项系统设置，手册当场卸载或恢复）；窗口不宽于 1120px、专注模式、搜索结果页、打印；开关设为「关」；省流量模式；低端设备（内存 ≤2GB 或 CPU ≤2 核）；**拿不到 WebGL2 上下文**（浏览器不支持，或像 Chrome 122 起那样默认不给软件渲染的 WebGL——这时页面安静回到没有手册的样子，控制台一个字都不打）；运行库加载失败、WebGL 上下文丢失；或者手册自己画一帧的耗时中位数与整页帧间隔中位数**同时**超标，持续累计 2 秒动画时间（两条线按档取，见下一条）：当场卸载，本次打开不再尝试。显示器刷新率低（50Hz、48Hz）、浏览器节能模式限帧（30fps）、以及页面自身因磨砂而掉帧，都不会触发这一条（只看帧间隔会把完全够用的机器误判成慢，所以要两个中位数同时超标）。设备不合格时开关也会自动撤掉。
- **「只有软件渲染」不再是不出现的理由，改成一个精简档（2026-09-23 加，四个工具同一套做法，刷刷先做通）。** 没有独立显卡的电脑（Windows 的 WARP、虚拟机里的 SwiftShader，屋主那台台式机就是）以前被整个拦下，现在照样能看到手册，只是走**精简档**：画布像素比钉在 1（物理像素长边再压到 640 以内）、每秒最多画 30 帧、关掉抗锯齿、不再跟着鼠标轻倾（翻页、开合、换业务这些照常）。**画质本身一点没砍**——纸纹、丝带、假投影、书页张数与中档完全相同，因为实测手册自己每帧只花 0.3–0.7 毫秒，瓶颈根本不在它身上。**精简档完全不看内存和核数**：屋主那台是 32G / 20 核，按内存核数会被判成最高档，软件渲染跑高档就是灾难。判定走两步：先按原来那套严格参数要上下文（有显卡的机器在这一步拿到，行为与以前一字不差），拿不到就放宽一次再要；另外再看一眼浏览器报的渲染器名，是 SwiftShader / llvmpipe / WARP（`Microsoft Basic Render Driver`）这类就直接按软件渲染办——这一条以前的作用是「拒绝」，现在是「判档」。帧率卸载那道闸在精简档下同步放宽（要连续两个统计窗口、间隔上限 1 秒），免得把它自己限的 30 帧误判成慢；**两条超标线按「本档自己承诺的帧率」写成倍数而不是固定毫秒**（间隔线 = 承诺间隔 ×2，自身绘制线 = 一整个承诺帧预算），**并且间隔取统计窗口内的均值而不是中位数**——限帧之后间隔只剩几个离散值，中位数会在临界点整体翻面，均值（＝这一窗口真送出去几帧）不会。这是四个工具通用的一条规矩：**护栏的判据里不许掺进我们自己加的量**，限帧器本身不受此约束（限帧是闸门，不是判据）。内存 ≤4GB 或 CPU ≤4 核的中档设备像素比上限 1.25，其余 1.75。三档完整参数表见 design-proposal.md §9.4b。
