新员工业务手册网站 v2.0.0

使用方法：
Windows：双击“双击打开手册网站.bat”，或直接双击 index.html。
Mac：双击“双击打开手册网站.command”，或直接双击 index.html。
     首次打开如被系统安全机制（Gatekeeper）拦下，提示无法验证开发者，
     请在该文件上点右键（或按住 Control 键点击），选择“打开”，
     再在弹窗中点“打开”确认一次，之后双击即可正常使用。

本网站为纯静态页面：手册正文和 114 张原始操作图片均保存在本文件夹内，不依赖刷刷软件。
默认按“办前准备 → 办理操作 → 办结核对 → 单据去向”分环节查看，也可切换“连续阅读”或“原文对照”。
材料、注意事项、交易入口和打印/传票/复审/签章索引均引用原句，点击可返回原文位置。
原文没有明确阶段、含并行情形或交错流程时，完整正文保留原序；准备页给出材料和注意事项入口。
“原文未注明”表示本手册未明确写出，不能理解成无需办理。单据索引不改变原文规定的办理时点。
正文恢复 Word 原有高光及红蓝等文字颜色，原始制度口径、图片和表格不作改写。
如需在手机或平板打开，请访问经过内部访问保护的手册网站；电脑本地预览仍可直接双击打开。
手册是内部资料，局域网或其他网络托管也须使用受控环境与访问保护，不要直接公开发布。

阅读界面：手机与平板优先（基础布局见 design-proposal.md §13，当前调整见 §14–15）
正文使用随窗口宽度变化的 17–20px 字号、1.8 倍行高和实色阅读底。
正文区域用满目录右侧的可用空间，不再整体限宽 1120px 或居中成窄柱；普通段落、步骤文字等最长 70em，
材料清单、图片和表格按各自内容使用正文空间，图片继续单列、保留原始尺寸与比例。
保留品牌顶栏的轻微玻璃感、外观三态与六个强调色；正文不再铺满玻璃卡片或背景光晕。
原有配色来源与历史核算见 design-proposal.md §10；版面与使用入口以 §13–15 的最新约定为准。

  外观  浅色（默认）/ 深色 / 自动。打开顶栏“工具”，在“外观”一排切换。
        “自动”跟随电脑系统的深浅设置，说明行会写明当前跟着系统解析成了哪一档。
        存在本机浏览器里，键名 hb:mode（存 light / dark / auto）。
        从旧版本升上来时：原来“界面主题”选过什么会自动接过来，不用重选。

  强调色  蓝（默认）/ 绿 / 靛 / 橙 / 粉 / 青，六个色圆点点一下就换，立刻生效。
        圆点旁的中文名平时收着，鼠标移上去或键盘走到时展开；读屏另有中文名，播报“强调色已切换为绿”。
        键盘可达：Tab 逐个走到，Enter 或空格都能切。
        存在本机浏览器里，键名 hb:accent（存 blue / green / indigo / orange / pink / teal）；
        没有存过、或存了不认识的值时一律用默认的“蓝”。浏览器禁用本地存储时只在本次打开内有效。
        旧版本存过的六套粉彩名（sky / mint / …）一律忽略，强调色从“蓝”重新开始。

  换了什么 强调色只改变品牌与强调控件的配色，不改变正文、排版和打印稿；
        打印使用浅色底，保留原文高光和文字颜色；两个外观开关不改变原文格式。

品牌图标可以自己换（不用改代码）
左上角那个圆角方块里的图标，放一个文件进去就换掉：
  assets/brand/brand-icon.svg   ← 首选
  assets/brand/brand-icon.png   ← 没有 svg 时用它，1024×1024
要求是透明底、白色线条（方块本身的渐变是页面画的）。图会自动缩到方块的 84% 并居中，放好刷新即可。
不放文件就是现在这枚内置的“打开的书”。详细说明见 assets/brand/README.txt。

浏览器标签页上那枚图标（favicon）是另一张，换法不一样
标签页那一格用的是 assets/brand/favicon.svg，跟上面那张“可换的品牌图标”是两份文件。
为什么不共用：上面那张是透明底白线（底色由页面画），拿去当标签页图标，压在浅色标签栏上就看不见了，
所以 favicon 另做了一枚“强调色渐变圆角方块 + 白线”，自带底色，浅色深色标签栏下都清楚。
换强调色时标签页图标会跟着换（六个颜色各一枚，由 app.js 按当前强调色现算）。
想换标签页图标：直接编辑 assets/brand/favicon.svg（里面就是一个圆角方块 + 几条白线，可以照着改），
同时要改 app.js 里 faviconSvg() 那一段——它生成的是同一张图，只是颜色按强调色现填，两处形状必须一样。
注意这是 XML：文件顶上的注释里不能出现两个连字符连写，写了整份文件就解析不了、标签页会变回空白。

窗口变窄时页面长什么样（断点见 design-proposal.md §13，宽度与层级调整见 §14–15）
  宽于 1100px   左侧业务目录 + 宽正文；点“目录”可收起或恢复左栏，右侧没有常驻速查栏。
  1100px 及以下 单栏阅读；点“目录”从左侧打开业务目录抽屉，选好业务后回到正文。
                分类（对私 / 对公）、目录过滤与常办入口在目录里；分类切换保留会话记忆。
                不再显示“最近查看”区域，也不再新增最近查看记录。
  所有宽度     顶栏保留搜索与“工具”入口；阅读导航用“目录”按钮和当前环节下拉定位。
                “准备材料 → 办理步骤 → 核对重点 → 办结归档”连续向下阅读，环节下拉只负责跳转。
                不再显示底部快捷栏和浮动的“下一环节”；正文末尾保留“回到目录”和“下一环节”按钮。
  工具抽屉     宽于 600px 从右侧打开；600px 及以下从底部打开，最高 85dvh，可在内部滚动。
                目录与工具一次只开一个；点关闭按钮、遮罩或按 Esc 退出，焦点回到打开它的入口。
                工具内提供业务速查、原图入口、打印、专注模式、外观与强调色设置。

正文怎么分清重点
  阶段编号与环节标题并排，小节与内容分组通过字号、间距和浅色组头区分，普通正文保持常规字重。
  材料清单使用统一列线：手机两列，较宽屏幕随可用宽度增加列数；长名称跨列且完整显示。
  同行项目等高，复选框对齐首行；每项至少 44px 高，方便手机点选。
  “清空勾选”保留功能但弱化外观；空环节用中性提示，原文中的风险块保留明确标签并加强背景区分。
  1101–1120px 区间显式使用单行网格，避免旧版两行布局把正文挤到下方留下大块空白。

图片怎么看
  114 张图片全部沿用 Word 中的原始文件，本版没有 AI 重绘、重采样或重新压缩。
  正文图片单图单行、保留完整自然比例，不再裁成固定高度的缩略卡片；小图标与短条不会强撑到整栏宽。
  点图片可放大查看、切换同业务图片，也可使用“原图”入口查看原始文件。
  部分原件本身是低分辨率拍屏或整页表单照片；放大能看大，不能恢复原本没有的文字细节。
  如需提高这类图的清晰度，应取得直接截图、原 PDF 或重新扫描的文件，并按数据再生成流程处理。

常用功能
  - 搜索业务名、单据或交易码，边输入边联想；用目录过滤快速缩小当前分类。
  - 材料清单可勾选，业务可加入常办；保留分类会话记忆，不再展示或新增最近查看记录。
  - 交易码可一键复制；正文可切换原文对照，保留原始制度口径。
  - 工具里可开启专注模式或打印当前业务，外观与强调色不影响打印稿。
  - 按 ? 查看快捷键，按 / 聚焦搜索；输入法选词中的回车、方向键与 Esc 归输入法。

怎么跑回归（只在改动站点代码时用得上，和双击打开手册没有任何关系）：
改完 index.html、app.js、styles.css 这类站点文件之后，可在仓库根目录执行已有基线对比：
  node tools/regress/run.mjs --baseline-ref <改动前的那个提交>
它拿那个提交当基线，对比全部 81 个业务、10 个搜索词与多个历史模式。
v1.8.0 改了导航、工具入口与布局，旧套件包含右栏和 3D 等历史结构断言；结构差异需要按本版目标复核，
不能把旧套件的通过记录当成本版验收。正文与数据一致性、当前抽屉/搜索/图片/打印交互须另行验证，
本轮实际结果以 design-qa.md 的对应记录为准。旧全量用时约 30 分钟；先冒烟确认环境的话加
  --modes default --nodes 3 --no-timing --no-mutation      约 1 分钟
需要 Node 24 以上和本机 Chrome（路径按 macOS 写死），调试端口固定 9241。
跑出来的 profile、快照、结果 JSON 全部写到仓库外的临时工作目录，不会落进仓库，
所以跑完 git status 应当是干净的。详见 tools/regress/README.md。
双击打开手册的人不需要装任何东西，本站运行仍然零依赖。

部署到网站（子域名托管）：
本站通过仓库根目录 Dockerfile 构建为只读静态容器。main 分支推送后，
GitHub Actions 会检查 JavaScript、核对 Dockerfile 带齐了页面要加载的每个本地文件
（tools/check-dockerfile-copy.sh，本机也可直接跑）、构建 sha-<完整提交> 镜像、发布到私有 GHCR，
确认包仍为 private，再通过 SSH 调用服务器部署入口。生产容器不映射宿主机端口；
公网只能经过 Cloudflare Tunnel、Nginx 网关和 Authentik 访问
https://gang.ysevan.com/ 。旧路径 /tools/ganggang/ 由主站 301 跳转。

本地验证：
  docker build -t ysevan-gang:test .
  docker run --rm -p 127.0.0.1:9082:8080 ysevan-gang:test

  为什么挂子路径不会出问题
  站内所有资源引用都是相对路径：index.html 里的 styles.css、四个外部 .js，
  app.js 生成的图片地址 assets/employee-handbook/imageNNN.png 或 .jpeg，全都不以 / 开头，
  因此不管挂在网站根目录还是 /tools/ganggang/ 下面，浏览器都按当前目录去取，一律取得到。
  业务深链用的是 # 号锚点（形如 #/0-0-1-2/1），# 后面的部分根本不会发给服务器，
  所以 https://你的域名/tools/ganggang/#/0-0-1-2/1 这种收藏链接在子路径下照常打开到同一业务同一环节。
  打印稿页脚那行深链是页面在打印时按当前地址现算的，不是写死的，
  所以在子路径下打印出来的纸面深链自带 /tools/ganggang/ 前缀，照着敲回来仍然落在同一处。

  认证与容器编排
  - Nginx 网关必须先执行 Authentik auth_request，再反代到 gang:8080。
  - Cloudflare Tunnel 只能连接 Nginx 网关，不能直接连接 gang 容器。
  - 仓库与 ghcr.io/ysevan/ysevan-gang 都必须保持 private。
  - 生产 Compose、健康检查、自动回滚和 GitHub Secrets 见 tools/deploy/README.md。
  - 认证对相对路径与 # 深链没有影响，授权后仍会直接落到对应业务。

数据再生成：
employee-handbook.js 和 assets/employee-handbook/ 下的图片，都是从 Word 版《新员工上岗手册》
自动导出的结果，不要手工编辑。手册出了新版需要重新生成时，用 tools/extract_employee_handbook.py。

  前提条件
  1. 源文档：Word 文件“新员工上岗手册（20260205）.docx”。
     现有数据就是由这个文件（2026-02-05 版）生成的。
     注意：原始 Word 不由 git 跟踪，也不随站点发布；重新生成前须取得维护者保管的原件，
     命令可以填写它的实际路径，不要把原件误加进仓库。
  2. 运行环境：Python 3，并安装 python-docx 依赖：
       Mac：  pip3 install python-docx
       Windows：pip install python-docx

  运行方式（在本文件夹内执行，下面是一整条命令，要写在同一行；
  文件名含中文括号，必须加引号）
    python3 tools/extract_employee_handbook.py "新员工上岗手册（20260205）.docx" --data-output employee-handbook.js --asset-dir assets/employee-handbook --report-output handbook-report.json

  四个参数的含义
    第一个参数        源 Word 文档的路径
    --data-output     生成的数据文件，正式生成时指向本文件夹的 employee-handbook.js
    --asset-dir       图片导出目录，正式生成时指向 assets/employee-handbook
    --report-output   生成情况报告（章节数、图片数、未被引用的图片等），仅供核对，
                      可以写到任意临时路径，不影响网站运行

  重要提醒
  - --asset-dir 指定的目录会被先整个删除再重建，不要指向存放了其他文件的目录。
  - 想先试跑看看效果，请把 --data-output 和 --asset-dir 指到本文件夹以外的临时目录，
    比对确认无误后再正式生成，避免覆盖现有可用数据。
  - 脚本只负责把 Word 内容导出成网页数据，不改写手册的制度口径；
    页面的展示逻辑在 app.js 中，与本脚本无关。
