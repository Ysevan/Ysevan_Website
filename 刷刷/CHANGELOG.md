## [3.12.0] - 2026-09-23

### 新增

- **学习统计页新增「按周回看」。** 页面顶部多一个分段控件「按周回看 / 累计统计」，默认按周回看；上次选哪个记在本机（`localStorage` 的 `shua-stats-tab`，读写抛错时按默认、不影响切换）。一周一屏 8 格：汇总占一格，加周一到周日七格，手机 2×4、≥901 为 4×2，正好填满。日期格左上是星期和日号、右上是当天合计题数，下面是当天做过的题库色块，每块带该库当天的题数，按题数从多到少排；一天超过 3 个题库时只列前 3 个，第 4 行是一块中性色「另 N 个题库 · M 题」，所以格子高度有上限、文字不截断。今天的日号套强调色圆底；未来的日子留空格子、半透明，也不计入汇总。左右箭头翻周（周一为一周的第一天）：到本周右箭头置灰；再往前一周整周都早于所有题库里最早一条记录时左箭头置灰。数据来自各题库各自的 `daily`，按日期并起来（当前题库取内存里的最新值），不改存储、不需要迁移。
- **汇总格只说事实。** 大字「本周做题 N 题」；下面第一行「D 天有练习 · 正确率 X%」，第二行和上周比「比上周多 N 题 / 比上周少 N 题 / 和上周一样」，上周没有记录时不写第二行；本周还没做题时第一行写「本周还没有练习」（往前翻的周写「这一周」）。**不显示任何时长**：`daily[].seconds` 是纯墙上时钟、没有发呆上限，连续刷题正常用还不结算，数字不可信（见 `design-proposal.md` 8.4）。
- **题库短名与色块颜色。** 9 个内置题库在 `app.js` 的内置题库定义里各有一个显式短名（年检2026、年检2023、国内结算、票据融资、银承2024、反假货币、对公外汇、警示教育、外汇一级）和一个固定颜色（6 个分类色 + 紫 `#AF52DE`、褐 `#A2845E`、黄 `#FFCC00`，不随强调色变），只用于显示、不写进用户数据；自建题库去掉 `【】` 及其中文字、取前 4 个字作短名，颜色按 id 的简单哈希落到这 9 色。色块是原色 14%（深色 20%）淡底 + 深一档的字，浅色、深色下文字对比度实测均 ≥4.5。
- **自动看题记住看到第几题，下次默认接着看。** 原来「自动看题」每次进去都是第 1 题，没有任何位置记忆（`startReviewSession` 里 `index: 0` 写死）。现在按连续刷题的办法把位置存进学习进度（`state.review = { index, signature, lastAt }`）：翻页、按题号跳转、自动翻页、暂停都会立刻存档，关标签页或换设备再打开都还在。再进「自动看题」时，如果题目集合和上次是同一批，就直接从上次那一题开始并提示「接着上次看到的第N题继续」；集合变了（换了题库，或在「专项练习」里另选了题型 / 题量 / 顺序）就从第 1 题开始，并提示「题目范围和上次不一样，自动看题从第1题开始」。看到最后一题再点「完成看题」算看完一轮，下次回到第 1 题——与连续刷题刷完一轮绕回第 1 题一致。
  - `signature` 不存整串题号（整库 799 条要 8KB 上下，而且每次翻页都要写一遍），存的是「条数 + 首尾题号 + 全部题号逐字算出的 32 位哈希」，例如 `799:annual-2026-single-001:annual-2026-judge-808:hrrn0g`。每个题号和它的位置都参与运算，对增题、删题、换序都敏感。
  - 备份规则照 `brush` 写：完整备份和选择性备份的「学习进度」都带上 `review`，合并导入时按 `lastAt` 取新的那一份，覆盖导入按来源那一份。
  - 老存档里没有 `review` 字段，读出来会补上默认值（当作没看过），不报错。

### 变更

- **会顶掉半截练习的入口，开始前先问一句。** 一次只存得下一个未完成会话，所以「开始新练习」等于放弃旧的那一场，而练习和模拟考试的作答只活在那一场里。现在 `startSession` 和 `startReviewSession` 在覆盖之前先看有没有「答过题、还没结算」的会话，有就用一句确认说清会丢什么：`上次的“模拟考试（100分）”做到第12/60题、已答11题。开始新的练习会放弃它的作答，无法恢复。要继续吗？`。点取消什么都不做，留在原地，那一场可以照旧从首页「继续上次学习」回去。
  - 模拟考试要到交卷才判分，做一半时只有已选答案没有判分记录，所以「已答」两处都算；多选题勾了又取消留下的空记录不算。
  - **被顶掉的是连续刷题或自动看题时不问**（位置分别另存在 `state.brush`、`state.review`）——顶掉它们不丢东西。问不问只看「会被顶掉的那一场」，不看从哪个入口进。
  - 刚点进去、一题还没答的会话也不算「半截」，不会问。
  - **「连续刷题」这个入口同样会问。** 它自己的位置另存在 `state.brush`，顶掉一个连续刷题会话不丢东西；但它一样会顶掉半截的专项练习或模拟考试，所以和别的入口一视同仁。续做连续刷题自己时仍然不问。
  - **确认窗排在「这次怎么刷」弹窗之前。** 顺序反过来的话，用户先挑一次答题方式、才被告知会丢作答，取消之后那次挑选白挑（而且偏好已经被记下了）。经过答题方式弹窗的入口在外层问一次，内层的同一道确认被压掉，不会连问两遍。
- **首页「自动看题」那一行写出将从第几题继续。** 用的是原来就有的右侧胶囊位（和「连续刷题」那一行同一个位置，没有新增元素）：有续做位置时标题变成「继续自动看题」、右侧显示 `5 / 799`；没有记录、或者上次看的是「专项练习」里挑的另一批题（签名不同、数字对不上），就不显示胶囊、标题仍是「自动看题」。
- **手机（≤600px）六处版式调整，只动手机档，600px 以上逐像素不变。** 屋主在手机上提的六条，按他看过的样张落地：
  - **顶部白带去掉**：≤600px 的顶栏（这一档只剩「品牌 + 刷刷」一条 56px 白带）整条隐藏，内容区顶部只留安全区 + 10px；品牌图标改成 30px 圆角块放进每一页大标题前面（`pageTitle()`，桌面 `display: none`），与侧栏那枚走同一条 svg → png → 内联的回落链；「更多」面板仍从底部弹出，上沿最多到安全区下 8px、矮屏放不下时面板内滚动；首页右上的「随机20题」在手机上不显示（专项练习里的「随机20题」一键选题照旧），错题与标记页同一位置的「练习当前题目」不受影响。
  - **首页统计卡排成 2×2**：四张卡两列，去掉小字说明和图标、数字 20px；今日复习、环形卡、最近学习仍各占一整行，学习统计页的卡面不变。
  - **搜题不显示解析**：手机上每道题只列题干、选项和正确答案。
  - **题库、题型两个下拉并排一行**：搜索框和「搜题」按钮各占一整行，放不下的题库名以省略号收尾。
  - **「今日已答」不再出圈**：环形卡改横排，圈缩到 56px、圈里只留数字（一天过千题时数字降到 14px），「今日已答 N · 每日目标…」挪到圈右边一行。
  - **首页副标题精简为「题库：XXX」**：模板里放长短两份、CSS 按断点切换，不在 JS 里判宽度；桌面文案逐字不变。
- 学习统计页原有内容（四张统计卡、各题型正确率、练习历史）整体归到「累计统计」页签，内容与口径不变，仍只看当前题库。
- 删掉学习统计页的「最近7天答题量」柱状图：它只看当前题库、按滚动 7 天算，已被按周回看完全覆盖。

  - **删除**「界面外观」：同一组浅色 / 深色 / 自动 + 六个强调色，电脑在侧栏底部、手机在「更多」面板里都有，数据管理页这份是第三份重复。

### 修复

- **「只备份部分内容」导出的文件用「覆盖」导入时，不带题库内容也会先确认。** 原来那句「确认覆盖导入所选题库的勾选内容？」只写在「文件带题库内容」那一支里；只勾了学习进度 / 收藏 / 不会标记 / 笔记导出的文件，改成覆盖再导入，会不问一句就用备份替换本机这些题库的记录。现在确认放在所有分支之前，点取消本机数据不变。「此备份不包含题库内容」的检查也挪到确认之前，不会先让人点确定再告诉他文件不对。

## [3.11.2] - 2026-09-23

### 新增

- **没有独立显卡也有精简 3D。** 屋主台式机（Windows + Edge 153）没有显卡，WebGL 走微软的软件光栅器 WARP（渲染器 `ANGLE (Microsoft, Microsoft Basic Render Driver … D3D11)`）。原来的门禁用 `failIfMajorPerformanceCaveat: true` 取上下文，软件渲染一律拿到 `null`，于是判成 `no-webgl`、整页永远是平面界面。现在这类机器走新增的**精简档 `soft`**：像素比封顶 1、画布物理像素长边 ≤640（CSS 尺寸不变，浏览器拉伸显示）、出帧限 30、关纸纹、几何细分取低档、上下文不开抗锯齿，并且**不跟指针轻倾、不随滚动后仰**——只在翻牌、答题、落堆这些离散事件时出帧。投影、叠卡张数、卡面字等其余画质与均衡档相同。「数据管理 → 界面动效」这时显示「这台机器没有独立显卡，3D用的是精简版，可能略慢；不想要可以关掉。」

### 变更

- **3D 门禁改两段式。** `effects.js` 先按原来的严参数取 WebGL2 上下文——有显卡的机器在这里拿到，之后按内存 / 核数 / 指针分高档、均衡档，与 3.11.1 一字不差；拿不到才用同样参数只把 `failIfMajorPerformanceCaveat` 改成 `false`、`antialias` 改成 `false`，换一块新画布再取一次。第二次拿到了就**一律**走精简档，完全不看内存、核数、指针，也不读写任何存储（屋主那台 32G、20 核、有鼠标，按旧判法会得高档，软件渲染跑高档就是灾难）。两段都拿不到（例如 Chrome 122 起默认不给 SwiftShader 的 WebGL）才 `fail("no-webgl")`，不重试、不提示；这时顺手探一次宽松参数的 WebGL1，只上报、不做场景。
- **帧守卫的判据由「中位数 + 绝对毫秒」改成「平均出帧率 + 按档目标帧率的比例」。** 原判据是最近 40 个帧间隔的中位数超过一个绝对毫秒阈值（高 / 均衡 28ms、精简 66ms），仿真下来它两头都错：卡顿让间隔成双峰分布，中位数只落在常见值上、完全看不见长尾——「60Hz 屏每 4 帧一次 120ms 卡顿」真实只有 **22.0 帧**，判正常（漏判）；反过来 30Hz 屏上完全流畅的 **30.1 帧**，因为 33.3ms > 28ms 判慢、把 3D 降档（误判）。现在量一个窗口（仍是 40 个间隔）的**平均出帧率**，与这一档自己的目标帧率按比例比：精简档目标就是自己限的 30 帧，低于 **0.6 × 30 = 18 帧**算一个慢窗口；高档 / 均衡档不限帧，目标是**屏幕实际刷新率**——没有 API 能问，用窗口内间隔的第 5 百分位估（最快的那批间隔代表屏幕节奏），夹在 30～120 帧之间，低于 **0.55 × 目标**算一个慢窗口。再加一条上限：出帧 **50 帧**以上一律不算慢，免得高刷屏上忽快忽慢时按估出来的 120 帧要求、反把好机器降档（144Hz 屏稳定送 64 帧的窗口会被 0.55 × 120 = 66 帧的线判慢）。连续几个慢窗口才动手没变（高 / 均衡 1 个、精简 2 个），动手的方式也没变：高档先降均衡档，均衡档再超就 `fail("slow")` 回平面、本次会话记住。精简档还把「超过多久不算一帧」的上限由 250ms 放宽到 1 秒——软件渲染真扛不住时一帧就可能超过 250ms，不放宽的话守卫永远攒不满样本、永远不动手。
- **精简档的限帧按「到期时刻」排。** 按「离上一帧多久」限帧时，软件合成下 rAF 只有 40 多帧，会被凑成每两拍画一次（无头 SwiftShader 实测 23.3 帧）；按到期时刻排，长期平均回到 30 帧（同条件实测 28.6）。卡顿之后不补帧。
- **`ShuaFx.status()` 暴露探测链**：新增 `tier`（`high` / `balanced` / `soft`，没有场景时为 `null`）、`stage`（`strict` / `loose` / `webgl1-only` / `none`，没探测过为 `null`）、`software`、`renderer`（取自 `WEBGL_debug_renderer_info`，拿不到为 `null`）与 `probe`（`webgl2Strict` / `webgl2Loose` / `webgl1Loose`，没试到为 `null`）。数据管理页据此多一行「探测：…；渲染器：…」，截这一段就能定位；`no-webgl` 按走到哪一段细分说法（「拿不到WebGL2」/「只提供旧版WebGL1」），原来「浏览器不支持WebGL2或只有软件渲染」的后半句已不成立，删去。
- **宽屏改为「等比放大、构图不变」。** 屋主在 Windows 大屏上看 3.11.1，觉得和 Mac 1440 的观感差太多：那一版字只涨约 1.15 倍、内容区却涨 1.36 倍还加了列，结果版面明显变密。现在整体等比缩放：引入长度单位 `--u: calc(clamp(1440px, 100vw, 2088px) / 1440)`——1440 及以下恰为 `1px`，往上与视口宽成正比（屋主台式 2040 视口为 `1.4167px`），2088（= 1440 × 1.45）起封顶 `1.45px`。样式表里随构图一起放大的 px 字面量全部改成 `calc(N * var(--u))`：字号、行高、间距与内边距、圆角、图标尺寸（导航 20、列表方块 32、色点 18、品牌方块 34）、控件高度、列表行高、侧栏宽、投影偏移，以及三个 3D 槽位的尺寸。随视口插值的那一组 token 在 `@media (min-width: 1441px)` 里换成「1440 处的值 × `--u`」：标题 34、h2 21.5、正文 15、间距 14.4、卡片内边距 17.3、侧栏 240、内容内边距 24。**不**乘 `--u` 的：媒体查询断点、1px 分隔线与亮线、`backdrop-filter` 的 blur、背景光晕的 vw 尺寸、焦点环的 2px。
- **为什么不是线性爬坡。** 定稿前用过「1441 起从 1px 线性爬到 2560 处的 1.45px」，它只在两个端点与等比重合、中间一律偏小：屋主台式实际视口 2040 处只有 1.2411px，比等比的 1.4167 小约 14%，整屏小一圈——这就是屋主反复说「和 Mac 差距大」的来源。等比公式在 2088 以内与「把 1440 版面整体放大」严格一致。

### 兼容性

- **1440px 及以下逐像素不变。** `--u` 在这些宽度上恰为 `1px`（`clamp()` 把视口宽夹在 1440，除以 1440 正好是 1），`calc(N * var(--u))` 与原来的 `N px` 数值完全相同；当时在 1440 / 1100 / 900 / 768 / 600 / 390 六个宽度上实测过首页截图与 3.11.1 字节级相同。**这条写在首页卡片网格改动之前，首页那一块已不再成立**，例外范围见下面单独一条。

- 有显卡的机器上 3D 的加载方式、三个场景、判定与降级链路都没变（实测默认 GPU：`stage` 为 `strict`、`software` 为 `false`、`tier` 为 `high`）；新增的只是软件渲染那一档。槽位跟着 `--u` 等比放大，场景按画布尺寸自行重算。

### 已知取舍

- 在 1440 → 1441 这一格的边界上，少数 token 会有一次小跳（侧栏 244.8 → 240.2、内容内边距 28.8 → 24、标题 34.16 → 34.02）：1441 起改用「1440 的设计值 × `--u`」，与 `clamp()` 在 1440 处的插值结果不完全相等；h2、间距、卡片内边距取的就是 1440 处的实际插值（21.5 / 14.4 / 17.3），几乎不跳。只有把窗口正好拖过这一格才看得到。
- **屋主两台机器的观感会不一样，这是预期。** 台式 2040@1.25 的 `--u` 为 1.417、未封顶，构图与 Mac 1440 一致；笔记本 2552@1.5 触了 1.45 封顶，构图比 Mac 紧约 18%（2552 / 1440 = 1.77，而 `--u` 只到 1.45），一屏看到更多。封顶是为了不让字号在超宽视口上无限放大；笔记本是高 DPI（物理约 3840 宽），1 CSS px 的物理尺寸比台式和 Mac 都小，封顶下正文的物理大小与 Mac 几乎相同。在屋主反馈前不为「两台一样」去改封顶值。
- **大屏首页要往下滚一点。** 屋主 2040×1019 的屏比 Mac 1440×900 扁（宽高比 2.00 对 1.60），内容高 ×1.417 而视口高只 ×1.13，首页需要滚动 312px（1440×900 是 42px、1440×720 是 222px）。接受滚动，构图与 Mac 一致；不做「竖向单独压缩」或「只压首页大卡高度」。做题页首屏（题干 + 选项 + 提交）在 1440×900 / 2040×1019 / 2560×1440 都一屏放得下。
- **精简 3D 在「软件合成」下仍会慢，瓶颈是玻璃模糊而不是 3D。** 没有显卡时浏览器通常连页面合成也改用 CPU（软件合成）。在本机用有窗口的 Chrome 加 `--disable-gpu --use-gl=swiftshader --enable-unsafe-swiftshader` 模拟、屋主视口 2040×1019@1.25：**3D 关着**、只让一个 24px 小方块在「今日复习」玻璃卡里每帧变色，页面就掉到约 4 帧；做题时点一下到下一帧约 150ms，3D 开关与否都一样。精简 3D 在这种环境下出帧只有 4–7 帧，帧守卫会在二十来题后把它关掉、回平面。把全站的 `backdrop-filter` 与光晕的 `filter` 去掉后，同样条件下精简 3D 稳定 30 帧、页面 50–100 帧。屋主那台 Edge 是不是软件合成，看 `edge://gpu` 的 Compositing 一行即可确认；若是，玻璃模糊要不要在这类机器上关掉是界面层的决定，本版没有动。

- 为 `env(safe-area-inset-top)` 和 `env(safe-area-inset-bottom)` 补上 `0px` 回退值。此前不带回退，浏览器一旦不认识 `env()`，包含它的整条 `calc()` 都会失效，手机端顶栏和底部导航的高度会一起失去约束；鸿蒙与部分安卓浏览器可能受此影响。有安全区的机型（iPhone 刘海屏）行为完全不变。
- 修复手机端搜题页搜索框与题库下拉之间出现约 316 像素空白的问题。`.search-form` 在手机端改为纵向排列后，桌面端用于设定宽度的 `flex: 1 1 360px` 变成了高度基准，360 像素被当作搜索框容器的高度；现在在手机端一并复位为 `flex: 0 0 auto`。影响搜题页和题库管理页的搜索框，只改变间距，不影响搜索行为和任何记录。
- 修复 Windows 上 `打开刷刷.bat` 只显示电脑地址、不显示手机访问地址的问题。电脑只有一块网卡时（最常见的情况），`serve.ps1` 里 `Sort-Object -Unique` 只返回单个对象，在单个对象上取 `.Count` 得到空值，被误判成“未检测到局域网 IPv4 地址”；现在结果统一按数组处理。影响启动窗口的提示文字，不影响服务本身、题库和学习记录，macOS 的 `serve.mjs` 原本就正常。

### 安全

- 容器版补齐与本机 `serve.mjs` / `serve.ps1` 相同的一组安全响应头：`Content-Security-Policy`、`Referrer-Policy`、`X-Content-Type-Options`、`Permissions-Policy` 和 `X-Robots-Tag`。此前 `docker/nginx.conf` 只设置了 `Cache-Control`，网站部署形态会丢掉禁止索引声明和这些防护头，不符合发布检查清单的要求。
