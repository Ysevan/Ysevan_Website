材质

液态玻璃怎么写、挂在哪、做不出来时怎么退、在没显卡的机器上要付多少；小屋那边是暖墨阴影和水彩绿植。颜色层级在色彩页，这里讲写法、降级与代价。

工具 · 液态玻璃

玻璃.62／.78、三团光晕的色值见色彩页「中性底与玻璃」「背景光晕」。这一章的样例里真的挂了磨砂：只在样例滚到视口附近时挂，滚走就摘。

液态玻璃＝半透明底＋两档模糊＋顶边亮线：侧栏30px·160%，卡片24px·150%

后面糊开、再提一点饱和度，上沿一道inset 0 1px 0的白线当受光的边。视口大小的面用重的一档，浮在内容上的小卡用轻的一档。

用在哪

plan：侧栏、tab bar、手机底部面板用重的一档（--blur-glass-strong），顶栏、详情对话框、菜单、提示条用轻的一档（--blur-glass）。会随正文长的面不在这里，见下面「磨砂放在哪」。本站：侧栏、顶栏、tab bar、「更多」面板都是30px·160%，条目卡不挂。

为什么

屋主要「参考苹果的UI和配色」；分层只靠玻璃、投影和分隔线，不用边框（反例在色彩页「中性底与玻璃」的对照里）。亮线放在阴影里，不占盒子、不改尺寸；浅色下.9的白很显，深色下只留.12。

固定的渐变背景画在body::before上；底色只写html，body透明

光晕是position:fixed; z-index:-1的伪元素，不用background-attachment:fixed。html和body都写了背景时，body的底画在光晕上面，把它整个盖掉。

用在哪

四个工具同一段；本站star.css第6节同样只给html写底。小屋走另一条路：暖雾直接写在body的背景上、background-attachment:fixed，规格写明这是「屋子不动，人在里面走」的观感来源。

为什么

只写body时，它的底会传给画布、画在最下面；html也写了，body的底就不再上交，画在body自己的盒子上——绘制顺序在z-index为负的伪元素之后，光晕被盖住。不用固定附着，是因为iOS Safari上它不生效，滚动时背景会跟着走。

坑

光晕被盖掉以后，离线算的对比度照样「成立」，脚本发现不了，只能看画面（刷刷2026-09-23验收时抓到的）。

有显卡的手机档（417×750@3.5走GPU）上，岗岗的浮层坏副本一个长帧都不多，交互页毛玻璃四种做法也分不出差别。本页那一行是反过来的提醒：快CPU扛得住这么小一块，代价只在慢机器上显形——判据先让它红过一次（每帧空转30ms时33.3ms、每秒长帧28个，判据是灵的），要看就在屋主那台上打开上面的「这台机器此刻」。

        

        
怎么量
相对判据：改动和基线跑同一串操作，交替跑3次合并，比整页requestAnimationFrame间隔的中位、P95，另数长帧（>25ms）的个数；要看合成器自己，另开tracing量每帧Display::DrawAndSwap。新加一块磨砂之前先做这个A/B。

        
为什么
CPU合成时，玻璃卡里任何一处重画都要重算整块模糊；砍3D画质（投影、张数、纸纹、分辨率）逐项都在噪声里。所以3D精简档只管少画、少出帧，不去碰界面层的磨砂。

        
坑
只看P95会漏掉稀疏卡顿：每次更新卡30ms的坏副本，卡帧不到总数5%，P95纹丝不动，必须另数长帧（让它红一次才发现）。无头Chrome每帧整屏重画，比有窗口时悲观，数字只当相对代价看；Windows的WARP未必和SwiftShader一样贵，屋主那台没实地量过。

三档各做什么

          
    
            
  • full：整页遮罩背景从清楚糊到26px（开1s、关.3s），只糊不压暗；弹层面板.88玻璃＋自己的磨砂。切主题的圆形揭开、强调色淡入、跨页过渡只在这一档做。
    • 
            
  • lite：遮罩不模糊、压暗淡入（浅rgba(20,24,36,.28)／深rgba(0,0,0,.5)），弹层面板不模糊、底提到.97；侧栏、顶栏、tab bar的常驻磨砂照旧。
    • 
            
  • off：同lite，并且常驻磨砂也关、玻璃提到近乎不透明，和「做不出磨砂」那套数一样。
    • 
          

        

        
为什么
代价不对等，往后果轻的那边错：误判成full，是没显卡那台整页卡；误判成lite，只是第一次打开少一点景深。所以没测过先按lite。过渡类只在full做，是因为View Transition要整屏截图，软件合成下最贵。降级的样子照交互页「毛玻璃浮层」的推荐：直接不模糊、压暗淡入、面板底提高，代价接近基线。

        
坑
无头Chrome测软件渲染，--use-gl=swiftshader要配--enable-unsafe-swiftshader才拿得到上下文；屋主的浏览器不会带旗标，带旗标那次的「能用」不能当结论。Windows还多一档WARP，macOS这边模拟不出来。圆环、刻度尺、照片抽屉三种弹层任何档位都只压暗。

为什么

/* 只在跨页过渡那一下起名：boot.js 在 pagereveal、star.js 在 pageswap 时挂 html.vt-nav */
html.vt-nav .side   { view-transition-name: star-side; }
html.vt-nav .tabbar { view-transition-name: star-tabbar; }
/* 侧栏的磨砂挂在侧栏自己身上，不挪到伪元素或子元素上 */
.side { -webkit-backdrop-filter: blur(30px) saturate(160%); backdrop-filter: blur(30px) saturate(160%); }

        

        
用在哪
本站切页时侧栏、tab bar原地不动，靠的是临时起名；平时不起名。任何用View Transition的玻璃站都会碰到：起了名的元素里面别再放要糊后面的玻璃。

        
为什么
backdrop-filter只往上糊到最近的backdrop root为止。起了view-transition-name、opacity小于1、带filter、clip-path、mask的元素都会成为这一层的根（Chrome 155逐个实测过；transform、will-change不会）——里面的磨砂只糊得到这层根自己画的东西，根后面的页面够不着。

        
坑
计算值照样是blur(…)：读getComputedStyle的量具看不出来，只能截图看。这一点是star第二阶段做跨页过渡时撞上的，所以侧栏的磨砂也别为了过渡方便挪到伪元素上。
