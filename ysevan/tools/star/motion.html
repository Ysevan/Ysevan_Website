动画

曲线怎么挑、补位怎么做、哪些属性能动、减弱动效怎么兜底、动画中途被打断怎么办；本站自己的几种过渡；小屋的开场、换房间和走进小屋。每条旁边都能点着看。按压倾斜、筛选让位、六种弹窗的手感在交互页，这里只讲通用的功夫。

通用

不分气质都适用。数值取自四个工具和小屋的代码；演示里的方块、卡片、文字都是示例。

一种动作配一条曲线：出现用缓出、离场用缓入、松手才带弹回；时长跟着路程走

局部小件140–260ms，整页过渡420–550ms，只有本身就是仪式的开场才上秒。同一个动作在一个站里只用一条曲线。

    为什么

    曲线说的是动作的物理：冒出来的东西一开始最快、落定时最慢；离开的东西慢慢起步、加速走掉；只有手松开的东西才会弹回来。时长跟路程走：按钮的反馈140ms就够，切页要盖住整屏，长一档；超过半秒的只留给不常发生、本身就是仪式的东西（开场写字、走进小屋）。plan把三档时长做成令牌，减弱动效时一处归零。

    坑

    同一种动作两处用两条曲线，手感就打架：岗岗速查卡抽屉特意跟目录抽屉用同一条.22s ease，两个底部抽屉手感相同。linear()弹簧要先写一行cubic-bezier再写一行linear()：不认它的浏览器丢掉后一行，留下前一行。

      function flipMove(items, mutate) {
  var before = items.map(function (el) { return el.getBoundingClientRect(); });  // 1、量旧位置：含上一轮没走完的位移
  items.forEach(function (el) { var a = running.get(el); if (a) a.cancel(); });  //    量完先撤掉上一轮
  mutate();                                                                     // 2、改 DOM：布局一次到位
  if (reduced()) return;                                                        //    减弱动效：只改不动
  items.forEach(function (el, i) {                                              // 3、量新位置
    var now = el.getBoundingClientRect();
    var dx = before[i].left - now.left, dy = before[i].top - now.top;
    if (Math.abs(dx) < .5 && Math.abs(dy) < .5) return;
    running.set(el, el.animate(                                                 // 4、从旧位置滑回0
      [{ transform: "translate(" + dx + "px," + dy + "px)" }, { transform: "translate(0,0)" }],
      { duration: 240, easing: "cubic-bezier(.2,.8,.2,1)" }));
  });
}

      为什么

      过渡width、left，每一帧都要重新排版，整排跟着重算；FLIP只在开头量两次，中间全是合成器上的transform。「让位」本来就是布局变了，让它一次到位，眼睛看到的连续交给反向位移。

      坑

      连点时上一轮还在半路：不先撤掉就量新位置，新位置里带着上一轮的位移，会一帧跳一截。量旧位置要用getBoundingClientRect（含正在走的transform），用offsetLeft量的是布局位置，同样会跳。验FLIP有没有动别读el.style.transform，见交互页筛选标签那条坑。

      只动transform和opacity；投影要变，就把大投影画在伪元素上去动它

      为什么

      合成器挪一张画好的图几乎不花钱；box-shadow每变一帧，浏览器就要把那一圈模糊重画一遍。屋主台式机没显卡，这一画全落在CPU上。小屋门厅的注释写得直白：动box-shadow本身等于每帧重画一大片模糊，实测掉帧就掉在这；挪到伪元素上用transform移，模糊只画一次。

      本页实测（2026-10-08，无头Chrome，左右各12张卡反复浮沉3秒，跑两轮）：A每一帧都在重画，Paint约2500次；光栅在2040×1019@1.25软件渲染下花了277–307ms，有显卡的1440档只花9–10ms；B的Paint约100次、光栅3–12ms。两边的帧间隔都是16.7ms：光栅在别的线程上，这么小的卡还压不垮帧；卡一大、一多（小屋门厅那张整卡、整页的投影），这笔账就落到帧上了。

      坑

      圆角不能跟着非等比缩放走（会拉成椭圆），动border-radius又违反规矩：岗岗灯箱的幽灵是直角的，接受头尾一两帧盖住缩略图的圆角。状态类（静态的opacity:0）不算动画。量帧率要断言操作真落地（真浮起了、真播了），不然「没动」会冒充「不卡」。

          为什么

          倒着走回去，要把动画当成可逆的状态机：每个中间态都得能往两个方向走，代码多一倍。开合只有零点几秒，用户几乎看不见那点连贯，直接到终态就好。走进小屋不一样：5秒、方向由用户自己的滚动决定，走到一半猛地跳回顶上像出了错，所以它值得倒放。

            用在哪

            门厅画内景深与走进小屋的场景，都只在夜里。

            为什么

            夜里的配方是「压暗偏冷＋门窗里的暖光＋8秒呼吸」：灯是活的，屋子才像有人。精简档砍它不是为了省那一点帧，是「停稳」能不能成立的前提：软件渲染上停在墙角后要按325万像素重画一张清楚的；呼吸留着，这一帧没机会发生，画出来也会被下一帧按走动密度盖掉，一块铺满视口的画布还会一直画下去。

            坑

            发现它靠的是读代码，不是验收：白天那次录像验的是「不闪」，验过了，可它测不到夜里压根没进入停稳那个状态。呼吸按绝对时钟走，夜里做逐像素比对会有1/255级的抖动，比之前要先把那块画布藏掉。
