动画

这一章写曲线和时长怎么选、补位怎么做、哪些属性可以动、减弱动效怎么兜底、动画中途被打断怎么处理，还有本站自己的几种过渡，以及小屋的开场、换房间和走进小屋。每条都带示例。按压倾斜、筛选让位和六种弹窗的手感写在交互页，这里只写通用的做法。

通用

这一组不分玻璃风和暖纸风，工具和小屋都适用。数值取自四个工具和小屋的代码，示例里的方块、卡片和文字只是占位。

曲线按动作选，时长按路程定

出现用缓出，离场用缓入，只有松手的东西带弹回。局部小件用140到260ms，整页过渡用420到550ms，超过一秒的只有开场这类仪式性的动画。同一种动作在一个站里只用一条曲线。

    用在哪

    本页每条示例的时长和曲线都取自这张表。交互页的按压倾斜、筛选标签和从毛玻璃浮层起的六种弹窗，是这些曲线用在实际界面上的样子。

    为什么

    曲线对应动作的物理过程。出现的东西一开始最快，落定时最慢。离开的东西慢慢起步，加速离开。只有手松开的东西才会弹回来。时长随路程变，按钮的反馈140ms就够，切页要盖住整屏，长一档。超过半秒的只留给不常发生、本身带仪式感的动画，比如开场写字和走进小屋。plan把三档时长做成变量，减弱动效时在一处归零。

    坑

    同一种动作在两处用了两条曲线，手感就不一致。岗岗的速查卡抽屉特意和目录抽屉用同一条.22s ease，两个底部抽屉手感相同。用linear()写弹簧时，先写一行cubic-bezier，再写一行linear()，不支持它的浏览器会丢掉后一行，用前一行。

    撑开、让位和补位用FLIP

    布局一次改到位，看起来的连续靠FLIP。先量旧位置，改DOM，再量新位置，用transform从旧位置滑回0。连点时，旧位置按此刻屏幕上的样子量，量完先撤掉上一轮动画。

    • 2026-09-27定

    本站用在类型单选（收藏页）搜索框（全站）

    示例点打乱、删一个、加一个看补位，切到直接跳可以对照。快速连点打乱按钮，现行写法每一下都从屏幕上的位置接着滑。打开反例后改成按布局位置量，不含上一轮还没走完的位移，连点时方块会一帧跳一截。

      数值和代码

      function flipMove(items, mutate) {
  var before = items.map(function (el) { return el.getBoundingClientRect(); });  // 1、量旧位置：含上一轮没走完的位移
  items.forEach(function (el) { var a = running.get(el); if (a) a.cancel(); });  //    量完先撤掉上一轮
  mutate();                                                                     // 2、改 DOM：布局一次到位
  if (reduced()) return;                                                        //    减弱动效：只改不动
  items.forEach(function (el, i) {                                              // 3、量新位置
    var now = el.getBoundingClientRect();
    var dx = before[i].left - now.left, dy = before[i].top - now.top;
    if (Math.abs(dx) < .5 && Math.abs(dy) < .5) return;
    running.set(el, el.animate(                                                 // 4、从旧位置滑回0
      [{ transform: "translate(" + dx + "px," + dy + "px)" }, { transform: "translate(0,0)" }],
      { duration: 240, easing: "cubic-bezier(.2,.8,.2,1)" }));
  });
}

      为什么

      过渡width、left时，每一帧都要重新排版，整排元素跟着重算。FLIP只在开头量两次，中间全是合成器上的transform。让位本来就是布局变了，所以让布局一次到位，看起来的连续交给反向位移。

      坑

      连点时上一轮还在半路。不先撤掉就量新位置，新位置里会带着上一轮的位移，方块一帧跳一截。量旧位置要用getBoundingClientRect，它含正在走的transform。offsetLeft量的是布局位置，同样会跳。检查FLIP有没有在动时不要读el.style.transform，原因见交互页筛选标签那条的坑。

      只动transform和opacity

      位置、大小和旋转用transform，出现和消失用opacity，这两样都在合成器上完成。box-shadow、width、clip-path这类属性每一帧都要重画或重排。投影要跟着变时，把整圈投影画在伪元素上，动它的opacity或transform。

      用在哪

      四个工具都把它写进了规矩，比如岗岗设计文档的动效口径一节、plan第34节、card的CLAUDE.md。小屋门厅挂画的大投影画在.set::before上，跟着倾斜移动时动的是transform。破例的只有两个进度圆环，刷刷结算的分数圈和岗岗的材料小圆环，动的是stroke-dashoffset，都先在没显卡的那一档量过帧率才放行。本站的按压倾斜、复制气泡和弹层也只动这两样。长代码的下拉展开动height，是写明了的例外，见交互页下拉展开。

      为什么

      合成器移动一张画好的图几乎没有开销。box-shadow每变一帧，浏览器就要把那一圈模糊重画一遍，屋主的台式机没有显卡，这部分全落在CPU上。小屋门厅的代码注释里写着，动box-shadow等于每帧重画一大片模糊，实测掉帧就出在这里，挪到伪元素上用transform移动后，模糊只画一次。

      本页实测（2026-10-08，无头Chrome，左右各12张卡反复浮沉3秒，跑两轮），A每一帧都在重画，Paint约2500次，光栅在2040×1019@1.25的软件渲染下花了277到307ms，在有显卡的1440档只花9到10ms。B的Paint约100次，光栅3到12ms。两边的帧间隔都是16.7ms，因为光栅在别的线程上，这么小的卡还不至于拖慢帧。卡片一大、一多，比如小屋门厅那张整卡或整页的投影，这部分开销就会落到帧上。

      坑

      非等比缩放会把圆角拉成椭圆，动border-radius又违反规矩，所以岗岗灯箱飞行用的那张替身是直角的，接受开头和结尾一两帧盖住缩略图的圆角。状态类（静态的opacity:0）不算动画。量帧率时要确认操作真的发生了（真的浮起了、真的播了），否则没动也会被当成不卡。

        动画的收尾和打断

        每段动画都能被打断。动画进行中再次触发，或者被别的途径关掉时，取消动画，删掉临时元素，清掉类名和计时器。零点几秒的开合直接跳到终态，走进小屋那种5秒的播放，往回滚时从这一帧原路倒放。收尾同时等事件和计时器，哪个先到用哪个，上一轮的收尾一律作废。

            长度要跟着卡片缩放。叶子大小、漂移幅度、推开的半径和力度都乘以卡宽除以708.08，不折算的话，大窗口上叶子显得小，推一下反应迟钝，看起来和卡片没有关系。刚度和阻尼比不乘，它们决定的是周期。

            夜里画中的灯会呼吸

            门窗的暖光乘上1加0.05乘sin(0.785t)，8秒呼吸一次，幅度5%。停下来以后只有它还在动，留着它，render()永远要下一帧，循环不会退出，停稳后重画一张清楚画面的那一步就永远等不到。所以软件渲染的精简档里把它关了，停在墙角时画面才能真正停下。

            用在哪

            门厅画内景深和走进小屋的场景，都只在夜里。

            为什么

            夜里的画面由三部分组成，压暗偏冷、门窗里的暖光和8秒一次的呼吸。灯在动，屋子才像有人住。精简档关掉呼吸不是为了省那一点帧，而是停稳这件事能不能成立的前提。软件渲染下停在墙角后，要按325万像素重画一张清楚的画面。呼吸留着的话，这一帧没有机会发生，就算画出来，也会被下一帧按走动时的像素密度盖掉，一块铺满视口的画布还会一直画下去。

            坑

            这个问题是读代码发现的，不是验收发现的。白天那次录像检查的是画面闪不闪，检查通过了，但它测不出夜里根本没进入停稳状态。呼吸按绝对时钟走，夜里做逐像素比对时会有1/255级别的抖动，比对前要先把那块画布藏起来。
