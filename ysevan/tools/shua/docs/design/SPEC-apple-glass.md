# 工具类项目统一视觉规格 · 苹果液态玻璃风（2026-09-23 屋主拍板，四个工具通用）

屋主原话：「刷刷的这些我觉得都不好看，你参考一下苹果的 UI 和配色」「UI 要适配我页面的缩放大小」「四个工具都用这套」。
本规格**替代**此前的「六套粉彩主题」方案（sky/mint/lilac/candy/mist/meadow 全部作废，不保留）。

视觉真源（只读）：`shua-glass.html`（同目录），浏览器直接打开；`?mode=dark`、`?accent=green|indigo|orange|pink|teal` 看变体；拖窗口看自适应。渲染图：`g1440-v3.png`（1440 浅色）、`gdark.png`、`gpink.png`、`g1100.png`、`g768.png`。各项目把这两个文件复制进自己的设计文档目录作真源。

## 1. 结构
- 左侧栏（玻璃）+ 内容区。侧栏：品牌图标 + 名字 + 一行说明；导航项 = **线条图标 + 文字**（图标 20px、stroke 1.9、不带底块，选中项图标与文字同为强调色）；分组小标题 11px 大写字距 .04em；底部：浅/深/自动分段控件、六个强调色圆点、版本、进度。
- 内容区：大标题（clamp 26–36px，字重 700，字距 -.4px）+ 灰色副标题；卡片网格 `repeat(auto-fit, minmax(190px, 1fr))`；分组列表（列表行 = 彩色圆角方块图标 32px + 标题/副标题 + 右侧计数胶囊 + 灰色 chevron），代替卡片网格里的入口卡。**样张此处是旧写法**（chevron 用的是字符「›」，导航图标 stroke 写的 1.8），**以 §5b 为准**：chevron 画成 SVG 线条图标，stroke 1.9。
- 主按钮：强调色渐变（accent → accent-2）白字，圆角 12，带强调色投影；次按钮：accent-soft 底 + 强调色字；第三级：玻璃底。
- 不用边框分层，只靠玻璃、投影和分隔线（rgba(60,60,67,.12)）。

## 2. 颜色（苹果系统色）
浅色：底 #F4F5F9；玻璃 rgba(255,255,255,.62)（强 .78）；玻璃顶边亮线 rgba(255,255,255,.9)；正文 #1C1C1E；次级 rgba(60,60,67,.62)；三级 rgba(60,60,67,.32)；fill rgba(120,120,128,.14)。
深色：底 #0B0C10；玻璃 rgba(40,42,52,.55)（强 .72）；亮线 rgba(255,255,255,.12)；正文 #F2F2F7；次级 rgba(235,235,245,.62)；fill rgba(120,120,128,.26)。
六个强调色（浅 / 深）：蓝 #007AFF/#0A84FF（默认）、绿 #34C759/#30D158、靛 #5856D6/#5E5CE6、橙 #FF9500/#FF9F0A、粉 #FF2D55/#FF375F、青 #30B0C7/#40C8E0。每个强调色配一个 accent-2（渐变浅端，见样张）和 accent-soft（12–20% 透明）。
语义色固定不随强调色：红 #FF3B30/#FF453A、绿 #34C759/#30D158、橙 #FF9500/#FF9F0A。
背景光晕：`body::before` 固定定位，三团 radial-gradient（blob1 跟强调色、blob2 暖色、blob3 冷色，透明度 .2–.55，blur 10px），深色下减弱。

## 3. 主题与切换
- `html[data-mode="light|dark|auto"]`（auto 跟 prefers-color-scheme）+ `html[data-accent="blue|green|indigo|orange|pink|teal"]`，默认 light + blue。
- localStorage 两个键：`<项目>-mode`、`<项目>-accent`；头部同步脚本在样式表前设好，免闪色；theme-color 跟底色（浅 #F4F5F9 / 深 #0B0C10）。
- 侧栏底部控件：分段控件（role=radiogroup）+ 六个色点（button + aria-pressed + aria-label 中文名，hover/焦点显示标签）。旧的六套粉彩键值一律回落默认。

## 4. 自适应（屋主明确要求）
- 字号、间距、侧栏宽全部 `clamp()` 随视口插值（样张 `:root` 里那组 --fs-*/--gap/--pad/--side-w）。
- 网格 auto-fit；列表行文字 ellipsis 不换行溢出；600–900px 侧栏收成顶栏（图标 + 文字横排可滚 + 末尾「更多」），内容单列；**≤600px（手机）用 iOS 式底部玻璃 tab bar**（玻璃底、顶边亮线、线条图标 + 短标签、选中项强调色），已有底部导航的项目（刷刷）照旧保留，主题控件放「更多」面板。
- 文字档：强调色/语义色当文字一律用苹果 HIG「增强对比度」浅色值：蓝 #0040DD、绿 **#1F7A36**（HIG 的 #248A3D 压白只 4.40）、靛 #3634A3、橙 #C93400、粉 #D30F45、青 #0071A4、红 #D70015；深色下用 HIG 深色增强对比度组：蓝 #409CFF、绿 #30DB5B、靛 #7D7AFF、橙 #FFB340、粉 #FF6482、青 #5AC8F5、红 #FF6961（靛在深色玻璃合成底上仍偏低，按实际底再提亮一档）。填充、渐变、图标、色点、焦点环仍用 §2 原值。
- **大屏（2026-09-23 两次修订，以第二版为准）**：内容区不得在侧栏右边孤零零居中成窄柱、两边大片空白。
  ~~初版（作废）：内容上限 1560、整壳居中、clamp 上端到 2000 视口、≥1600 多列。~~ 屋主在 **2560 CSS px** 的 Windows 屏上看刷刷 3.11.1 后说「跟 mac 的差距很大，希望跟 mac 一样」——初版在 2560 下视口涨 1.78 倍而字号只涨 1.13–1.18 倍、内容宽涨 1.36 倍再拆多列，版面变密、构图也变了。
  **现行规则：按比例放大，构图不变。** ① ≥1600 不增加列数，一律保持 1440 的构图；② 尺寸以 1440 为基准随视口等比放大、2560 处约 **1.45 倍封顶**（标题 34→49、正文 15→22、次级 13→19、间距 ×1.45、侧栏 240→348、图标/控件/圆角/行高/方块图标同比），1440 及以下数值不得变；③ 内容宽 = **视口 − 侧栏 − 左右内边距，铺满，不设硬上限、不做整壳居中留白**（内边距同比 24→35）；④ 不许用 CSS zoom。
  **「填满」与「严格等比」冲突时取填满**（2026-09-23 裁定）：1.45 封顶下 1440 构图 ×1.45 = 2088 < 2560，二者不可兼得。取填满——屋主最初的抱怨里就包含「左右两大块空白」，留 200+px 边等于把他抱怨的东西还回去。代价是卡片/列表轨道比严格等比宽约 28%、侧栏占比从 16.7% 降到 13.6%，字号、列数、图标、间距、行高一律不受影响。多出来的宽度只许被卡片与列表轨道吸收，不许拿去加列。
  **2026-09-23 屋主实机实测，纠正一处前提**：他那台 Windows 的**视口不是 2560 CSS px，是 2040**（DPR 1.25——物理 2560 宽，Windows 显示缩放 125%）。此前所有「2560」的推算都建立在错误前提上。两个后果：
  ① **1.45 封顶在他机器上根本触不到**（1.45 要到 2088 CSS px 才封顶），他实际拿到的就是纯等比 2040/1440 = **1.417**。也就是说「填满 vs 严格等比」那个取舍**在他的机器上不成立，两者恰好一致**，之前那段权衡只对 2088 以上的视口才有意义。
  ② **公式必须是「视口 ÷ 1440」，不能是「1440→2560 的线性爬坡」。** 两种写法在 2560 处都等于 1.45，但中间全程不同：在 2040 处，等比给 1.417，线性爬坡只给 1.241，**小 14%**。card（`clamp(1440px,100vw,2088px)/1440`）和 plan（`视口/1440`，上下限 1 与 1.45）写的是等比，**刷刷写成了线性爬坡**（`min(calc(1px + (100vw - 1440px) * 0.000401786), 1.45px)`），所以刷刷在他屏幕上比另外两家小一圈——这正是他反复说「刷刷跟 mac 差距大」而 card 没这个问题的原因。统一写法以 card 为准。

  **2026-09-23 晚，第三台设备的数据到了——屋主有两台 Windows，视口不同，两台都要验：**
  | 机器 | 视口 | DPR | 显卡 | --u |
  |---|---|---|---|---|
  | 台式（无显卡，WARP 软件渲染） | **2040 × 1019** | 1.25 | Microsoft Basic Render Driver | 1.417（未封顶，纯等比） |
  | 笔记本（RTX 4060 Laptop） | **2552 × 1274** | 1.5 | NVIDIA RTX 4060 | **1.45（封顶）** |
  ① **2552 那台会触到 1.45 封顶**，所以「填满 vs 严格等比」的取舍在它上面是真实存在的：严格等比只要 2151 宽、会留约 400px 空白，填满给 2134 宽的内容区、卡片与列表轨道比等比宽约 23%。**裁定不变，取填满**（理由同上：他最初的抱怨里就有「左右两大块空白」）。
  ② **验收一律两档都拍**：2040×1019 与 2552×1274，各一张，再各附一张缩到 1440 宽的对照。只验一档会漏——1.45 封顶只在 2552 那档显形。
  ③ 3D 在两台上表现相反：2040 那台只有软件渲染、走精简档；2552 那台 RTX 4060 硬件加速、严格探测直接通过、走完整档。**「为什么没有 3D」这个抱怨只属于 2040 那台。**

  **验收判定（比数值重要）**：把 2560 的截图等比缩到 1440 宽，与真实 1440 截图并排，列数、各块相对大小、文字占行比例应肉眼无明显差别。交付截图加 1920、2560 与这张缩放对比图。
- 浏览器缩放（⌘+/-）等价于视口变窄/变宽，不允许出现横向滚动条、不允许固定像素布局把内容挤出去。

### 4b. 大屏规则（2026-09-23 控制室**修订**，四家统一）
起因：屋主在 Windows 大屏上看（控制室起初按 2560 CSS px 下发；2026-09-23 实机测得视口是 **2040×1019、DPR 1.25**——2560 物理 × 125% 显示缩放，当时写「以后大屏截图与验收一律用 2040×1019」，**已被共用源 §4 的两台设备表取代：2040×1019 与 2552×1274 两档都拍**），要的是「跟 Mac 1440 一样」的观感——**构图不变、整体等比放大**。当天早些时候那版（抬 clamp 上限 + ≥1600 分节两列）作废：把字和间距各自往上插值、再多排一列，等于在大屏上塞更多东西，不是放大。

1. **以 1440 为基准等比放大，2560 处 1.45 倍封顶，1440 及以下一个数都不变。**
   `:root { --ui-scale: clamp(1, tan(atan2(100vw, 1440px)), 1.45) }`——`tan(atan2(<长度>, <长度>))` 是 CSS 里把两个长度约成**无单位比值**的唯一办法（Chrome 111+ / Safari 15.4+ / Firefox 118+）。
   兜底：`@supports not (scale: tan(atan2(1px, 1px)))` 里按 1600/1800/2000/2200/2400/2560 六档写死 1.11 / 1.25 / 1.39 / 1.45 / 1.45 / 1.45。
   **探针必须用 `scale:` 而不是 `width:`**：tan/atan2 求出来是无单位数，`width: <number>` 在支持三角函数的浏览器里照样非法，用 width 会让 `@supports not` 恒为真、把写死档位盖到所有浏览器上（2026-09-23 Chrome 实测）。
2. **每个尺寸 token 写成 `calc(clamp(下限, 原斜率, 该 token 在 1440 处的值) * var(--ui-scale))`。** clamp 的上限封在 1440 值，所以 ≤1440 时 `--ui-scale` 恒为 1、clamp 也没到顶，数值与改版前逐位相同；>1440 时 clamp 已封住，只由 `--ui-scale` 放大。圆角同样乘 `--ui-scale`（不跟着放大会显得棱角变硬）。
3. **CSS 里写死的像素，凡影响构图的一律乘 `var(--ui-scale)`**：图标块、控件高度、栏宽、槽位、顶栏高、日期带、3D 摆件槽位等。因为 ≤1440 时它恒等于 1，这个乘法在小屏上是彻底的 no-op。**不许用 CSS `zoom`。**
4. **壳与内容区（2026-09-23 第二次修订：取「填满」）**：壳不设 `max-width`、不居中、不留白。内容宽 = 视口 − 侧栏 − 左右内边距，铺满；多出来的宽度只许被卡片与清单轨道吸收（plan：`--content-max` 在 ≤1440 是 880px，>1440 放开成 100%），**不许加列、不许改字号 / 图标 / 间距 / 行高**（这些继续只走 1.45 封顶的 `--ui-scale`）。理由：屋主最初的抱怨里就有「左右两大块空白」，整壳居中留白等于把它还回去。
5. **不增列**：宽屏不排两列、不改分节结构；任何宽度仍不允许横向滚动条；≤900px 顶栏形态、≤600px 底部 tab bar 不受这条影响。

## 5. 降级与可访问性
- **降级探针必须同时测前缀形式**（2026-09-23 控制室实测后加的硬规则，四家统一）：
  ```css
  @supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) { /* 玻璃提到 .9 不透明 */ }
  ```
  **不许**写成 `@supports not (backdrop-filter: blur(1px))`。iOS Safari 18 以前只认 `-webkit-backdrop-filter`，不认不带前缀的形式——只测不带前缀的那条，`not` 在这些浏览器上恒真，会把明明做得出磨砂的设备打到不透明兜底档，表现就是「手机上玻璃全变成实心白块」。实测：shua / gang / plan 三家都写错了（各 1、3、1 处），只有 card 写对。
  `prefers-reduced-transparency`：同上；`prefers-reduced-motion`：光晕静止、过渡关闭。
- **两条声明一律 `-webkit-` 在前、标准在后**：`-webkit-backdrop-filter: X; backdrop-filter: X;`。过 Vite 8（lightningcss）构建的项目里，标准声明写在前面会被压缩器合并掉，产物只剩前缀那条（plan 2026-09-23 实测，`build.cssTarget` 拦不住）。静态站不过构建，顺序不影响结果，但四家统一这么写，省得以后某家接了构建再踩一遍。
  出货 CSS 里两条必须成对出现，数量相等（实测现状：shua 11/11、gang 8/8、card 7/7，都已成对）。
- 对比度：正文/次级对玻璃（叠最亮光晕角）≥4.5；主按钮白字对渐变浅端 ≥4.5（不够就把 accent-2 压深，蓝的 #5AC8FA 需压到约 #2F9BF5）；焦点环 2px 强调色 offset 2px。
- **2026-09-23 屋主看过 card 后改定（替代上面「主按钮白字 ≥4.5」与压深渐变的说法，四家统一）**：
  ① ② **主按钮 = 左上角品牌图标同款渐变 + 白字，浅色深色都一样**：浅色 accent→accent-2 用样张 `shua-glass.html` 的原值（蓝 #007AFF→#5AC8FA、绿 #34C759→#A8E063、靛 #5856D6→#BF5AF2、橙 #FF9500→#FFD60A、粉 #FF2D55→#FF9AA2、青 #30B0C7→#64D2FF；深色蓝 #0A84FF→#64D2FF，其余深色按同样亮度配），按钮与品牌图标共用同一个 `linear-gradient(135deg,var(--accent),var(--accent-2))`，不许另配一套更深的，深色用深色强调色同样做法。屋主原话「所有颜色的按钮色可以和页面左上角的颜色一样浅一点」。白字对浅端实算只有 蓝 1.90 / 绿 1.55 / 靛 3.52 / 橙 1.41 / 粉 2.02 / 青 1.72（岗岗实算），按钮字 14–15px 不够 WCAG 大字标准，**不要用「大字 3:1」口径粉饰**；四家统一写成「审美优先的可读性例外」，文档列真实比值，对比度脚本把主按钮归「记录不断言」。补救（不改渐变）：主按钮文字加 `text-shadow:0 1px 2px rgba(0,0,0,.25)`，四家统一。压深的「文字档」只用于正文/链接/chip 文字。
  ③ 浅色次级文字 rgba(60,60,67,.62) 叠最亮光晕角只有 3.42；~~统一改 .73~~ **统一改 .76**（见 §5c——.73 只压过蓝光晕，其余五色的 blob 更深，只有 4.28–4.49）；三级 .32 只用于 chevron/装饰，不承载文字。
  ④ 深色靛文字 #7D7AFF 统一提亮到 **#8E8BFF**（对 #0B0C10 6.8）。
- 磨砂只放在视口大小的表面（侧栏、卡片、列表），长内容区不加 backdrop-filter（岗岗 2026-09-22 实测过显卡纹理上限问题）。
- **本项目本地记录（plan，2026-09-23）**：浅色次级字**再压深到 rgba(60,60,67,.85)**（统一值 .76 压玻璃六色全过，但 plan 内容区大量文字直接压光晕、没有玻璃底；详见 §5c 末尾）。输入框占位字统一落到 `--text-muted`（Chrome 默认 #757575 在深色玻璃上只有 2.97）。
- **本项目实现注记**：`@supports` 探针与 `-webkit-` 在前的顺序都已照做（`tokens.css` 末尾与 `App.css` 文件头注释）；lightningcss 压缩产物里探针本来就会被补成两种写法，但 dev 预览不过压缩，所以源码必须自己写对。

## 5b. 图标（屋主 2026-09-23 两次纠正后的硬规则）
- **一律用真正的 SVG 线条图标**（stroke **1.9**、圆头圆角、20px 导航 / 18px 列表；四家代码实测都是 1.9，2026-09-27 统一写死），**禁止用字符或 emoji 凑图标**（▶ ◔ ? ✕ ★ 这种一律不行），禁止灰色空方块占位。
- 列表行的图标底块：32px、圆角 9、语义/分类色实底 + 从上到下 22%→0 的白色高光渐变 + 顶边 1px 内亮线 + 轻投影，像 iOS 设置的图标块；图标白色线条，实心只用在 play 这种本来就是实心的形。
- 导航图标不带底块，颜色 = 次级灰，选中变强调色。
- 图标集统一：优先 SF Symbols 的形（不能用 SF 字体，但按它的几何画），项目里已有的 SVG 图标改成同一 stroke 风格即可，样张 `shua-glass.html` 里的 17 个 SVG 可直接复用。

## 5c. 次级字统一值与各项目自测义务
- 浅色次级字统一 **rgba(60,60,67,.76)**（2026-09-23 控制室裁定；此前 .62 → .73 都是只压蓝光晕算出来的，绿/橙/粉/青/靛的 blob 更深，.73 只有 4.28–4.49）。一个值，不按强调色分表。深色次级仍 rgba(235,235,245,.62)。
- `--fill` 一律实色：浅色 = 白与 `--ink` 兑 11%，深色 = 深底与 `--ink` 兑 20%（岗岗实测半透明 fill 会把光晕吃进来，同色相文字压它只有 3.9–4.4，contrast 不可预测）。
- 「填满」裁定只管壳、卡片网格、列表轨道；**长文本阅读行宽不铺满**（正文、搜索结果这类仍居中收在 --measure 内）。
- **各项目必须在自己最不利的光晕角下实测 ≥4.5，不够就本地再压深并在设计文档记录**，统一值只是起点不是免检。

## 5d. 对比度验收方法（四家统一）
两条路都要跑，互相补位：
1. **公式法压最不利角**：对每个文字色，底色取「玻璃 rgba 叠在 body 光晕最亮/最暗那一角」的合成色（不是取屏幕像素平均，也不是取玻璃的名义值），用 WCAG 2.x 相对亮度公式算比值。半透明字色先按 alpha 压在这个底上合成再算。断言：正文/次级 ≥4.5，图形 ≥3，高对比 ≥7。
2. **像素法交叉验证**：真实页面逐元素截图，取元素底色像素众数（含磨砂与光晕的最终合成），与元素前景色算比值。浅/深 × 六强调色 × 全部承载文字的元素类型。
3. 两条路各抓得到对方漏掉的东西（岗岗实例：公式法抓到粉色光晕下顶栏当前环节名 4.35、半透明 fill 轨道上的次级字 4.1；像素法抓到深色弹层底太亮导致三个强调色选中项 4.17–4.25），所以**任一条不过都算不过**。
4. 主按钮白字对亮渐变归「记录不断言」，脚本单列真实比值，不许改判定口径粉饰。
5. 一键脚本（岗岗 scratchpad/glass-gang/contrast.mjs：headless Chrome + CDP，file:// 打开，逐元素截图取众数；公式法为 node 一行 L/C 函数）：
   ```js
   const L=h=>{const [r,g,b]=[1,3,5].map(i=>parseInt(h.slice(i,i+2),16)/255).map(c=>c<=0.03928?c/12.92:Math.pow((c+0.055)/1.055,2.4));return .2126*r+.7152*g+.0722*b};
   const C=(a,b)=>{const x=L(a),y=L(b);return ((Math.max(x,y)+.05)/(Math.min(x,y)+.05)).toFixed(2)};
   ```

**plan 本地实测与压深记录（2026-09-23，公式法 + 像素法，脚本 `formula.mjs` / `pixel.mjs` 在 plan 子代理 scratchpad `49549089…/scratchpad/contrast/`，临时目录，结论以本节与 proposal §8.3 为准）**
- plan 的结构和另外三家不同：**内容区没有玻璃底**，日期分组、「今天 1 项 · 约 2.5 小时」、分节标题、日期带、「9月23日 — 9月25日 · 无安排」都直接压在光晕上。所以最不利角除了「玻璃叠光晕」，还要算「裸底叠光晕」。
- 光晕可达强度（实测每档视口里「离 blob1 中心最近的裸底文字」）：blob1 在侧栏 / 顶栏下面，内容区最多吃到 1100 0.60、1440 0.68、2040 0.66、**2552×1274 0.82**、768 0.10、390 0；blob2（右上）与 blob3（底边 70%）的中心本来就在内容区，按满强度算。
- 统一值 .76：压玻璃六色全过（最低 4.62 靛）；压裸底 blob3 满强度六色都只有 4.1–4.2，blob1×0.82 靛 3.79。**本地压深到 .85**：裸底最低 **4.58**（浅靛，blob1×0.82），玻璃最低 5.83；像素法 1440 六色 × 浅深本轮范围最低 5.27（深绿侧栏副标题），裸底最低 5.55。一个值不按强调色分表。
